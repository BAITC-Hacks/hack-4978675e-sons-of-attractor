# Frontend: передача для интеграции

Реализовано по `front_tz.md` и разделу 4 `backend_tz.md` из предоставленных материалов. Только HTML/CSS/JavaScript, без сборки, runtime-зависимостей, CDN и внешних шрифтов. Порядок `(-E, price_from_kzt, id)` принадлежит API; frontend сохраняет полученный порядок. Политика H из старой идеи не используется.

## Состояние

Фронтенд готов к подключению нормативного API: форма, проверка ввода, три исхода, до трёх карточек, источники и маркировки, применение подсказок и другого города, объяснение смены даты, обработка ошибок и устаревших запросов. Адаптивная верстка проверена на ширинах 1440, 390 и 360 px.

Backend подключён: `docker-compose up --build -d` поднимает API и этот frontend на http://localhost:8000. Демо проверяются на реальном CSV; контрактные ответы остаются только в тестах. Семантическая проверка ответа внешней модели требует действующего API-ключа.

Добавлен ввод текста через `POST /api/parse-request`. Возможность включается по `meta.ai.text_input.enabled`; без ключа textarea и кнопка недоступны, форма работает. Полный однозначный результат заполняет форму и запускает поиск; неполный или неоднозначный очищает пропущенные поля и требует уточнения. Редактирование формы/текста отменяет устаревший разбор. `meta.ai.answers` независимо описывает настройку объяснений.

Режим ответа `live_quotes` обозначает цитаты, выбранные моделью и сверенные с исходным описанием; он не равен `approved_facts` и не меняет порядок карточек. `answer_generation` показывает `disabled`, `generated`, `fallback` или `not_needed`. Правила ключей и модели описаны в корневом README на английском.

## Подключение к FastAPI

Приложение ожидает один origin без CORS и без отдельного frontend-сервера:

| URL | Что отдаёт backend |
|---|---|
| `/` | `frontend/index.html` |
| `/styles.css` | `frontend/styles.css`, CSS |
| `/app.js` | `frontend/app.js`, JavaScript-модуль |
| `/lib/contracts.mjs` | JavaScript-модуль |
| `/lib/format.mjs` | JavaScript-модуль |
| `/api/meta` | Справочники, окно дат, версии и пресеты |
| `/api/recommendations` | POST с параметрами и окончательной выдачей |

Для `.mjs` нужен JavaScript MIME type (`text/javascript` или `application/javascript`). Индекс также работает при раздаче frontend в отдельном пути с завершающим `/`; ресурсы относительные, `/api/*` остаётся в корне origin.

Не отдавать HTML вместо ошибок `/api/*`. Служебные `.tools/`, `.artifacts/`, `tests/` и этот файл не нужны в публичной статике: достаточно перечисленных пяти файлов. Основному приложению не нужны npm install или Node.js. Корневые README, Compose и серверную раздачу должен подключить backend-исполнитель.

## Контракт

Фронтенд не содержит справочников, фильтров каталога, ранжирования или готовых демо-результатов. Все примеры приходят из `meta.demo_queries`; нажатие отправляет обычный запрос. Без `/api/meta` форма недоступна, показана повторная загрузка.

Запрос: `city`, `date`, `event_format`, `category`, `budget_kzt`, `duration_hours`, `language`. Опциональные пустые значения передаются как null. Бюджет — положительное безопасное целое JS; часы — положительное конечное число. Дата остаётся календарной ISO-строкой, без часового пояса.

Ответ: `status`, `query`, `summary`, `cards`, `counts`, `diagnostics`, `suggestions`, `city_alternatives`, `versions`, `explanation_mode`, `warnings` по backend_tz. Даже пустые списки и nullable-поля должны присутствовать согласно контракту. `shown_count = min(3, eligible_count) = cards.length`.

`versions` содержит `dataset`, `facts` (string/null), `algorithm`. Сравнение даты выполняется только при одинаковых версиях и остальных полях запроса. Занятость определяется только по новому `diagnostics.exclusions`; отсутствие в top-3 само по себе не доказывает занятость.

Подсказка должна менять ровно одно заявленное поле, включать весь новый `query` и увеличивать число показанных вариантов. Приложение не вставляет ожидаемые карточки: запрашивает сервер снова. После редактирования формы подсказки прошлого ответа скрыты.

HTTP 422: `{ "error": { "code": "validation_error", "message": "...", "fields": { "date": "..." } } }`. Ключи fields совпадают с именами полей запроса. Для 500/503 нужен такой же envelope с нейтральным сообщением; frontend показывает свой безопасный текст. Ошибки парсинга и нарушения контракта отделены от пустой выдачи.

## Проверки

Из корня репозитория, Node.js 20+:

```sh
node --test frontend/tests/contracts.test.mjs
```

Браузерные проверки требуют Playwright и установленный Google Chrome. Это только инструменты разработки; каталог `.tools` игнорируется Git:

```sh
npm install --prefix frontend/.tools --no-save --package-lock=false playwright@1.58.2
node frontend/tests/browser-check.mjs
```

В Windows PowerShell, если исполнение npm.ps1 запрещено, использовать `npm.cmd` вместо `npm`. Можно задать `BROWSER_CHANNEL=msedge`, если установлен Edge вместо Chrome.

Тестовый сервер временно слушает случайный порт на 127.0.0.1. API-ответы подставляются только внутри Playwright через перехват запросов; ни приложение, ни сервер статики не имеют встроенного mock API. `tests/fixtures.mjs` — контрактные примеры для проверки UI, не реализация подбора и не источник истины для бизнес-данных.

Покрыты: пустые/невалидные значения, границы календаря, безопасные числа, null, сохранение порядка, три исхода, источники, синтетические и оценочные данные, подсказки, другая дата/город, устаревший ответ даже при проигнорированном AbortSignal, 422/500/503/сеть, таймаут 12 секунд, повтор, безопасный внешний текст, длинный контент, мобильная ширина, клавиатура и structured_only.

После исправлений из `fix_front.md` проходят 10 модульных и 18 браузерных проверок. Добавлены регрессии видимости результата после примеров и подсказок, отсутствия лишней прокрутки и влияния устаревших ответов, смены режима фактов в обоих направлениях и склонения числа профилей. Предупреждение о фактах отделено от ошибки справочников; принятый результат отображает собственный режим и версии.

Для проверки готового настоящего сервиса, без перехвата API:

```sh
node frontend/tests/browser-check.mjs --live http://127.0.0.1:8000
```

Режим `--live` проверяет контракт каждого пресета через реальный API и первый сценарий в браузере. Полную приёмку всех настоящих сценариев, объяснений и счётчиков дополнительно выполнить по front_tz/backend_tz. Он не проверяет правильность бизнес-алгоритма только по совпадению формы JSON.

Снимки экрана записываются в игнорируемый `frontend/.artifacts/`. Они сделаны на явно обозначенных тестовых ответах, а не на работающем бэкенде.

## Для README общей поставки

- Раздавать frontend тем же FastAPI-процессом, что и API.
- Установки npm для пользователя нет, внешние ресурсы при открытии не загружаются.
- Пять обязательных полей; язык/длительность необязательны. Категории не сужаются при смене города.
- При пустой выдаче пользователь может явно применить проверенное сервером изменение даты/бюджета или поиск в другом городе.
- Основные аргументы и цитаты приходят от backend; UI не генерирует объяснения и не заявляет независимую проверку подрядчика.
- После готовности API пройти пресеты 13/14 ноября, редкую категорию, отсутствие категории, декабрьскую занятость, бюджетный порог и два лайв-бэнда; записать результаты и реальные времена.
