# Подготовка AI-реестра — B3

Код подготовки и загрузки реализован. Реальное извлечение 66 профилей ещё не
выполнено: в доступном окружении отсутствуют ключ и название модели.
`backend/data/facts.json` не создаётся из тестовых данных. Пока файла нет,
приложение работает в `structured_only` и возвращает предупреждение.

## Извлечение

Используется OpenAI Responses API со
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Модель задаётся явно через `OPENAI_MODEL`; она должна поддерживать Responses
и строгую JSON Schema. Ключ берётся только из `OPENAI_API_KEY` окружения процесса.
Не сохраняйте ключ в репозитории, промпте или реестре. `.env` автоматически не читается.
Отдельные SDK и новые зависимости не нужны.

Команды из корня репозитория:

```powershell
backend/.venv/Scripts/python -m backend.ai.prepare extract
```

Передаются только ID, description и допустимые форматы каждого профиля.
Сохранённые инструкции находятся в `prompt.txt`, схема ответа модели —
`output.schema.json`. Отправляются 66 отдельных запросов, максимум два факта
на профиль, `store=false`. Любой отказ, неполный ответ или ошибка прерывает
подготовку: непроверенные данные не заменяют действующий реестр.

После успешной обработки всего каталога создаётся `backend/data/facts.pending.json`.
Все записи, в том числе пустые, имеют статус `pending`. Сохраняются реальная
модель из ответа провайдера, запрошенное имя модели, метод `responses_api`,
хеш промпта, исходного CSV и каждого description после CSV-разбора.
ID факта детерминированно выводится из ID профиля, цитаты и связанных форматов.
Существующие файлы скрипт не перезаписывает: для новой попытки задайте новый
`--pending` и впоследствии новый `--facts`.

## Отдельная содержательная проверка

Просмотрите каждую запись pending вместе с полным исходным description:

- Цитата точная, сохраняет субъект, отрицания, ограничения, числа и единицы.
- Формат прямо подтверждён цитатой. Поле event_formats и рекламные обобщения
  сами по себе не доказывают связь; «деловые встречи» не означают корпоративы.
- Из упоминания услуг не следует их включение в стоимость.
- Пустая запись также проверена: полезные конкретные сведения не пропущены.

Автоматическая проверка подстроки не заменяет эту содержательную проверку.
Если цитата или форматы требуют исправления, сначала исправьте pending,
затем заново рассчитайте его SHA-256 и составьте отчёт проверки.

Отчёт — JSON с решением для каждого ID, включая профили без фактов:

```json
{
  "pending_sha256": "SHA-256 байтов проверенного pending-файла",
  "reviewer": "фактический проверяющий",
  "method": "executor_review",
  "profiles": [
    {
      "contractor_id": "ID из pending",
      "accepted_fact_ids": ["принятый ID факта из pending"],
      "note": "Конкретный результат проверки цитаты и связи с форматом"
    }
  ]
}
```

`executor_review` означает проверку исполнителем; `human_review` указывается
только если её действительно выполнил человек. Пустой `accepted_fact_ids`
отклоняет все факты записи и даёт `no_usable_facts`. Отчёт обязан покрывать
все ID ровно один раз, даже если пустых фактов много.

```powershell
Get-FileHash backend/data/facts.pending.json -Algorithm SHA256
backend/.venv/Scripts/python -m backend.ai.prepare accept --review backend/data/facts.review.json
backend/.venv/Scripts/python -m backend.ai.prepare validate
```

В отчёте используйте SHA-256 в нижнем регистре. Принятие создаёт
`backend/data/facts.json`; в нём сохраняются сведения о проверяющем и хеш pending.
Сохраните рядом pending и отчёт для воспроизводимости. Повторная генерация моделью
может изменить факты; детерминизм поиска гарантируется для сохранённого снимка.

## Использование приложением

`FACTS_PATH` выбирает принятый реестр. При старте проверяются схема, покрытие ID,
статусы, хеш CSV, хеши описаний, точность цитат, уникальность фактов и форматы.
Ошибка хотя бы одного профиля отключает весь реестр. Отсутствие CSV по-прежнему
даёт 503; проблема только с фактами допускает рабочий `structured_only`.

При принятом реестре порядок — `(-E, price_from_kzt, id)`; E определяется
только фактами о запрошенном формате. Допуск кандидатов по структурированным
полям не расширяется. Карточка содержит принятую цитату с `fact_id` в evidence.
Более полный выбор различающих объяснений между карточками относится к B4.

После подготовки запуск и поиск не требуют API-ключа и не обращаются к провайдеру.
Версия `facts` равна SHA-256 байтов принятого файла. Загрузка производится один раз
при старте, поэтому смена реестра требует перезапуска приложения.

## Проверено

102 теста B1–B3 прошли. Для B3 использованы явно тестовые реестры и имитация
ответа провайдера: проверены формат запроса, pending, отдельное принятие,
полное отключение несовместимого реестра, рейтинг E и запуск без ключа.
Это не подтверждение реального AI-извлечения или проверки содержания 66 профилей.
